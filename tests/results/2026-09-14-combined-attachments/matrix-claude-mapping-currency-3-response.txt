## Runtime and control (step 3)

- **Hosting placement** is not in the decision. In-process versus hosted runtime is the first fork, and session lifecycle and isolation follow from it. This needs a decision before design closes.
- **Ingress and binding** are the live concern for delegation. The peer's ingress must be reachable, and A2A binding compatibility, JSON-RPC versus HTTP plus JSON, is recorded as unverified. Agent-card discovery is the step that establishes it. Do not delegate until it is checked.
- **Lifecycle** matters to the session responsibility. If the agent is hosted, the session cannot be assumed to outlive the host's idle and reclaim policy. Design the interaction so a reclaimed session is a visible restart, not silent state loss.
- **Identity** is only an identifier when propagated. If corpus retrieval or the peer requires acting as the calling user, that needs an explicit delegated-access consent step.
- **Human authority** is not invoked by any of the four responsibilities as stated. If a gate is added later, the handoff transition is where a workflow-level gate would sit. Per-call approval and consent are separate layers and do not substitute for it.

## Assurance (step 4)

- **Observe**: capture session turn boundaries, retrieved passages with their source, any handoff transition, and each delegated task with its returned result. The agent's own narration does not count.
- **Evaluate**: check that later turns correctly use earlier ones, that citations trace to real corpus passages, and that delegated results match the task sent.
- **Verify behaviour**: confirm the single agent actually varies its next step. If it never does, re-route down to a bounded call. If the optional handoff never fires in practice, remove it rather than carry it.
- **Regress**: re-run these checks after any SDK update. The framework's .NET availability status is unverified and the quick start still uses a prerelease flag, so drift is a live risk.
