**What it is**

- `SupportEmail` → `SpamClassifier.classify()` → `Decision(outcome, decided_by, reason, verdict, request_id)`.
- Rule layer runs first (`rule:blocked_domain`, `rule:allowed_domain`, `rule:known_thread` via a callback into your ticket store). Nothing hits the model if a rule fires.
- Otherwise one `client.messages.parse()` call on `claude-opus-5`, structured output into `SpamVerdict` (`is_spam`, `confidence`, `category`, `reason`), effort `low` since this isn't intelligence-bound.
- Three outcomes, not two: `spam`, `not_spam`, `undecided`. `undecided` covers low confidence (`min_confidence`), refusals, rate limits, 5xx, and connection errors — so an API outage degrades to "a human looks" rather than dropping customer mail. Other 4xx re-raise, because that's a bug in the code or config.
- It never touches the mailbox. Quarantining is the consequential step whose authorization policy is still *unknown — governance decision required*.

**Two things to know**

1. Your installed SDK is `anthropic` 0.75.0, where `parse` lives only under `client.beta.messages`. The code targets the current 1.x surface (`client.messages.parse`) — run `pip install -U anthropic` before the `__main__` demo.
2. A phishing email can occasionally trigger a safety refusal on Opus 5; the code treats that as `undecided`. If you'd rather the API retry on a fallback model server-side, there's a `fallbacks` parameter for that — I left it out because it needs the beta client and I couldn't verify it composes with `parse()` on the installed SDK.
